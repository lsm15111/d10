# AI 구조 (첨부안 검토)

기준일 2026-10-29 · 상태: 제안 (AI1~AI6 결정 전) · 그림: [ai-v3.2.svg](../architecture/ai-v3.2.svg) · 전체 구조: [system-v3.2.svg](../architecture/system-v3.2.svg)

## 결론

- **뼈대는 맞다:** 입력 → 에이전트 → RAG 검색 → PostgreSQL(pgvector) + LLM. 벡터 DB를 따로 두지 않고 PostgreSQL 하나에 pgvector를 쓰는 것, 업체 추천을 DB 조회와 조건 거르기로 시작하는 것은 그대로 쓴다.
- **숫자는 옮긴다:** 첨부안은 '소요 기간', '조건 기반 필터링', '적합도 판단'을 LLM이 한다. 믿집 규칙(AGENTS.md 3장)에서는 기간 · 날짜 · 점수를 계산 엔진(`calc`)이 만들고, LLM은 설명과 후보 중 고르기만 한다.
- **커뮤니티 글은 뺀다:** 이용약관 · 저작권 · 개인정보 문제가 있다. 업체 평점 · 후기는 PO 결정(2026-10-29)으로 화면에 둔다.
- **에이전트 하나를 더한다:** 요구사항 v3.2의 확정 공정표(FAG-03). 첨부안은 두 개다.
- **RAG는 작게 시작한다:** 도배 · 목공 시공 가이드는 처음에 수십 건이다. 문서 표에 공정 · 주제 꼬리표를 붙여 SQL로 고르고, 문서가 늘면 같은 표에 임베딩 열을 더해 pgvector로 넘어간다(AI1).

## 첨부안 판정

| | 첨부안 | 판정 | 이유 |
| --- | --- | --- | --- |
| 1 | 기본 정보: 지역 · 집 종류 · 평수 · 준공 연도 · 예산 · 스타일 · 특이사항 | 유지 | 스타일 · 특이사항은 3번 자유 글로 받는다 |
| 2 | 선택 공정: 도배 · 목공 · 타일 · 전기 | 바꿈 | 1차 범위는 도배 · 목공(AGENTS.md 1장). 도배 유형(저가형 · 기본형)과 목공 항목을 받는다 |
| 3 | 추가 요청사항(자유 글) | 유지 | 지금 화면에는 없다(AI2). 연락처 · 주소를 가린 뒤 프롬프트에 '자료'로만 넣고, 지시문으로 읽히지 않게 구분한다 |
| 4 | 에이전트 2개 | 바꿈 | v3.2는 예상 공정표 · 업체 추천 · 확정 공정표 3개다 |
| 5 | 예상 공정표가 '소요 기간(참고)'을 만듦 | 바꿈 | 기간 · 날짜는 calc(품 0.5 올림, 휴무일 데이터)가 만든다. LLM은 작업 설명 · 주의사항 · 준비할 일을 쓴다 |
| 6 | 공공데이터(건축 기준 · 노임비)를 RAG로 | 바꿈 | 단가는 `ref_prices` 표에 적용일 · 버전과 함께 둔다. 벡터 검색은 '비슷한 글'을 찾을 뿐 정확한 값 · 최신 값을 보장하지 않는다 |
| 7 | 커뮤니티 데이터(공정 일정) | 뺌 | 남의 글을 모으는 것은 이용약관 · 저작권 · 개인정보 문제가 있고 품질을 확인할 수 없다. 나중에 믿집에서 끝난 공사 일정(고객 동의)으로 대신한다 |
| 8 | 업체 추천: 조건 필터링 · 적합도 판단을 LLM이 | 바꿈 | 거르기는 SQL(승인 · 시공 지역 · 공정 · 일정), 점수는 calc, LLM은 상위 후보 중 3곳과 이유만. 후보에 없는 id는 버린다(GovBiz에서 효과를 본 계약 검사) |
| 9 | 업체 후기 · 평점 | 유지 (PO 결정) | 화면의 '믿집 기록' 묶음에 둔다. 지금 값은 예시 데이터이고, 후기 기능을 만들 때 확정 업체 고객만 쓰게 한다. 추천 점수에 쓸지는 AI5와 함께 정한다 |
| 10 | 예산으로 업체 거르기 | 바꿈 | 업체 가격대 데이터가 없고 가견적은 업체가 프로젝트마다 쓴다. 예산은 표준견적서와 비교해 안내하는 데만 쓴다 |
| 11 | RAG 검색 '레이어' | 바꿈 | 따로 두는 층 · 서비스가 아니라 `app/agent/retrieval.py` 함수 하나 |
| 12 | LLM: OpenAI API, 상황별 모델(GPT-4o · GPT-4.1 · GPT-4.1 mini) | 바꿈 | 공급자는 ADR로 하나 정하고 작업별 모델을 적는다(AGENTS.md 4장). 모델 이름은 정하는 날 공급자 목록으로 다시 확인한다 |
| 13 | (없음) 검산 · 기록 · 실패 처리 | 더함 | 아래 '공통 규칙' |

## 에이전트별 흐름

| 에이전트 | 1 | 2 | 3 (LLM) | 4 검산 (실패하면 버림) |
| --- | --- | --- | --- | --- |
| 예상 공정표 FAG-01 | 프로젝트 답 · calc 공정표 초안 | 문서 고르기: 공정별 시공 가이드 · 체크리스트 | 작업 설명 · 주의사항 · 준비할 일 + 근거 문서 id | 날짜 · 기간이 calc와 같은지, 목공 → 도배 순서, 휴무일 |
| 업체 추천 FAG-02 | SQL 후보: 승인 · 시공 지역 · 공정 · 일정 | calc 점수로 상위 10곳 | 3곳 + 추천 이유 | 후보 밖 id, 지역 밖 업체(치명 오류) |
| 확정 공정표 FAG-03 | 확정 업체가 등록한 공사기간 | calc: 반나절 단위 공정표 | 순서 설명 · 할 일(관리사무소 신고 등) | 휴무일 작업, 겹침, 도배가 목공보다 먼저 |

- 세 에이전트 모두 worker 안에서 돈다. 프로젝트를 저장하는 트랜잭션에 `jobs(project_created)` 행을 남기고, worker가 결과를 각 기능 service에 넘겨 저장한다.

## 공통 규칙 (AGENTS.md 4장 그대로)

- LLM SDK 호출은 `app/agent/llm.py` 한 곳. 출력은 Pydantic 스키마로 검사한다.
- 실행마다 입력 스냅숏(개인정보 가림) · 모델 · 프롬프트 버전 · 토큰 · 비용 · 시간을 `jobs` 행에 남긴다.
- CI는 스텁(`LLM_LIVE=false`)으로 돌고 유료 호출은 0회다. eval 세트는 추천 20 · 공정표 15건.
- LLM이 실패하면 계산 결과만 보여 주고 "설명을 만들지 못했어요"라고 알린다. 화면에는 AI가 쓴 글이라는 안내를 단다.

## RAG 데이터

- **표:**
  - `rag_documents`: 출처, 제목, 주소, 이용 조건, 버전, 적용일, 수집일, 공정, 주제
  - `rag_chunks`: 문서 id, 순서, 본문, 공정, 주제, (2단계) `embedding vector(N)`
- **1단계 (문서 수십 건):** 공정 · 주제 꼬리표로 SQL 고르기. 고른 문서 id를 근거로 넘긴다. 임베딩 공급자 · 수집 작업이 필요 없다.
- **2단계 (문서가 늘거나 완공 사례를 넣을 때):**
  - pgvector: DB 이미지를 `postgres:17-alpine`에서 `pgvector/pgvector:pg17`로 바꾸거나 확장을 설치하고, migration에 `create extension vector`를 넣는다.
  - HNSW 색인을 만들고, 공정 · 주제 조건을 붙인 검색은 0.8.0부터 생긴 반복 색인 스캔(`hnsw.iterative_scan`)을 켠다.
  - `vector`형 HNSW 색인은 2,000차원까지라서 임베딩 모델을 고를 때 차원을 확인한다.
- **넣는 문서:** 팀이 쓴 공정별 시공 가이드 · 체크리스트, 이용 조건을 확인한 공개 기준 문서, 고객이 동의한 믿집 완공 사례.
- **넣지 않는 것:** 커뮤니티 글, 지어낸 사례. 업체 평점 · 후기는 RAG 문서가 아니라 업체 표의 값으로 읽는다.

## 정할 것

| | 질문 | 권장 |
| --- | --- | --- |
| AI1 | RAG 시작 방식 | 꼬리표 SQL 고르기로 시작 → 문서가 늘면 pgvector |
| AI2 | 추가 요청사항(자유 글)을 받을지 | 받음: 선택, 500자, 연락처 · 주소 가림 |
| AI3 | LLM 공급자 · 작업별 모델 · 임베딩 모델 | **결정: 공급자 OpenAI** (2026-10-29, [ADR 0003](../adr/0003-openai-rds.md)). 작업별 모델 · 임베딩 모델 이름은 정하는 날 확인 |
| AI4 | RAG 문서 출처 | 팀이 쓴 가이드 + 이용 조건을 확인한 공개 문서. 커뮤니티 글 제외 |
| AI5 | 업체 추천에 예산을 쓸지 | 거르기에 쓰지 않음, 표준견적서와 비교 안내만 |
| AI6 | 후기 · 평점 | **결정: 화면에 그대로 둔다** (2026-10-29). 추천에 쓸지만 남음 |
