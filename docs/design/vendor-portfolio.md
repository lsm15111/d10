# 업체 포트폴리오 설계 (도배 · 목공 시공 사례)

기준일 2026-10-29 · 상태: 제안 (13장 결정 전)

## 1. 목표와 원칙

- **사례 1건 = 공사 1건.** 공정별 정해진 항목과 사진 묶음으로 만든다. 사진마다 역할(시공 전 · 중 · 완공), 공간, 디테일 종류, 전후 짝을 붙인다.
- **영감보다 검증.** 오늘의집 집들이는 가구 · 소품을 갖춘 '보기 좋은 집'을 요구한다. 믿집은 시공 품질을 판단하게 하는 곳이라, **완공 전경 + 이음매 · 몰딩 연귀 같은 근접 컷 + 같은 각도의 전후 사진**을 기본으로 한다.
- **가장 강한 신뢰 신호는 '믿집에서 진행 · 완료한 공사'와 연결된 사례다.** 고객이 동의하면 배지를 붙인다. 외부 공사는 '업체 등록 사례'로 따로 표시한다.
- **위치는 시 · 군 · 구까지가 기본이다.** 단지명은 고객이 동의할 때만 보인다. 동 · 호수 칸은 아예 두지 않는다.

## 2. 다른 서비스는 어떻게 하나

| 서비스 | 사례에 적는 것 | 사진 구성 | 신뢰 신호 |
| --- | --- | --- | --- |
| 오늘의집 (전문가 시공사례 · 집들이) | 필수: 공간 유형, 평수, 가족 형태, 작업 분야. 권장: 지역, 스타일, 시공 범위 | 자연광 전경을 대표로, 도면 → 현관 → 거실 · 주방 → 침실 → 욕실 순, 공간마다 문제 · 개선 · 자재 이유 | 집들이는 등급 업체만 신청, 약 3일 검수(어둡거나 흔들림, 워터마크, 빈 공간은 반려). 리뷰에 '오늘의집 계약' 표시 |

## 3. 사례 1건에 적는 것

### 공통

| 항목 | 필수 | 값 |
| --- | --- | --- |
| 제목 | ✓ | 40자 이내. 예: 마포구 30평대 실크 도배 · 천장 몰딩 |
| 공정 | ✓ | 도배 · 목공 (하나 이상) |
| 집 종류 | ✓ | 아파트 (1차) |
| 지역 | ✓ | 시 · 도 + 시 · 군 · 구 |
| 단지명 | | 고객이 동의한 경우만 공개 |
| 평수 | ✓ | 10평대 ~ 50평 이상 (견적 받기와 같은 구간) |
| 공간 | ✓ | 거실 · 주방 · 방 · 현관 … 여러 개 |
| 끝난 달 · 걸린 기간 | ✓ | 2026-10 · 2일 |
| 비용 | | 공개 안 함 / 구간 / 정확한 금액 (13장 결정 3) |
| 설명 | ✓ | 공간별 2~3문장: 기존 상태 → 한 일 → 자재를 고른 이유 |

### 도배

- 벽지 종류(필수): 실크 / 합지(광폭 · 소폭) / 기타(패브릭 · 기능성)
- 천장 포함(필수), 기존 벽지 철거, 초배(없음 · 부분 · 전체 · 띄움시공)
- 끝선 마감: 몰딩 위 / 무몰딩 / 마이너스몰딩
- 자재: 브랜드(목록 + 기타) · 제품 라인 · 품번 · 색 이름 · 붙인 곳(벽 · 천장 · 포인트 벽). 품번 규칙은 브랜드마다 달라서 자유 입력으로 받는다.

### 목공 (항목마다)

- 항목: 천장 몰딩, 걸레받이, 문선, 문틀, 문짝, 천장 평탄화(우물천장), 등박스, 벽 평탄화, 가벽, 기타
- 형태: 평몰딩 · 계단형 · 마이너스 · 무몰딩
- 높이 · 폭(mm), 소재(MDF · PVC · 원목 · 석고 · 합판), 마감(필름 · 도장 · 시트), 철거 포함 여부, 적용 공간

## 4. 사진

### 사진마다 붙이는 것

- **역할(필수):** 시공 전 · 시공 중 · 완공
- **공간(필수):** 3장의 공간 목록에서 고른다.
- **디테일 종류:** 전경, 이음매, 천장 경계선, 몰딩 끝선, 콘센트 · 스위치, 모서리, 무늬 맞춤, 몰딩 연귀, 걸레받이 틈, 문선, 문짝, 평탄화 천장, 등박스, 타카 · 퍼티, 코킹
- **전후 짝:** 같은 자리에서 찍은 시공 전 사진과 완공 사진을 묶는다. 묶인 사진은 고객 화면에서 비교 슬라이더로 보인다.
- **설명:** 80자 이내
- **대표 사진:** 1장. 완공 전경 중에서 고른다.

### 공정별 꼭 넣을 사진 (게시 조건)

| 공정 | 필수 | 권장 |
| --- | --- | --- |
| 도배 | 완공 전경, 이음매 근접(빛이 옆에서 드는 각도), 천장 경계선 또는 몰딩 끝선 | 콘센트 · 스위치 재단, 모서리, 무늬 맞춤, 같은 각도의 시공 전, 초배 중 |
| 목공 | 완공 전경, 몰딩 연귀 근접, 걸레받이와 바닥 사이 또는 문선 | 몰딩 옆 단면(줄자와 함께), 문짝 · 경첩, 평탄화 천장(시공 전 우물천장과 짝), 등박스 점등, 타카 자국 퍼티 · 코킹 |

전체 5~40장. 모든 사진이 처리 완료이고, 개인정보 검토에서 걸린 것이 없어야 게시된다.

### 업체에게 보여 줄 촬영 안내

- 낮에 찍고 실내등도 켠다. 흔들림 · 워터마크는 안 된다.
- 전경은 가로로, 방 모서리나 문틀에서 가슴 높이로 찍고 세로선을 맞춘다.
- 이음매 · 평탄도는 창이나 조명이 옆에서 비출 때 잘 보인다.
- 시공 전 사진을 찍은 자리에서 완공 사진도 찍는다(같은 높이 · 같은 렌즈).
- 찍기 전에 액자 · 가족사진, 우편물 · 택배 송장, 현관 번호, 창밖의 동 번호를 치운다.
- 긴 변 1,200px 미만은 받지 않고, 2,000px 미만이면 알려 준다.

## 6. 개인정보 · 법

이 장은 법률 자문이 아니다. 조문은 법제처에서 다시 확인한다.

- **고객 동의:** 고객 집 사진에 단지명 · 평수 · 시공 시기가 붙으면 세대를 알아볼 수 있다. 동의 범위 · 시각 · 약관 버전을 기록하고, 철회하면 바로 내린다.
- **시공 전 사진 속 사람:** 이전 거주자 등은 동의를 받거나 가린다.
- **공개 금지:** 동 · 호수, 주소, 현관 번호 · 도어락, 가족사진, 우편물, 창밖으로 동 번호가 보이는 컷, 서류 · 달력, 아이 이름표.
- **위치 정보:** 공개용 사진에서는 EXIF · GPS를 반드시 지운다. 원본은 비공개로만 둔다(보관 기간은 13장 결정 4).
- **표시광고법:** 남의 시공 사진을 내 사례로 올리기, 공사 범위 과장, 인증 거짓 표시는 문제가 될 수 있다. 인테리어 시공사례 제재 선례는 찾지 못했다(비슷한 서비스업 제재는 있음).
- **추천 · 보증 심사지침(2024-12 시행):** 사진 공개에 보상(할인 등)을 주면 그 사례 · 후기에 그 사실을 표시한다.
- **약관:** 업체 콘텐츠는 믿집 안 노출로만 쓰고, 삭제 사유 · 절차를 적고, 업체가 사진 권리를 보증하게 한다. 공정위가 2024-12에 인테리어 플랫폼 6곳 약관을 고치게 한 내용이 이 부분이다.

## 7. 이미지 처리

### 처리 순서 (arq 워커)

1. 형식(파일 앞부분)과 크기 · 픽셀 수를 확인한다(압축 폭탄 방지).
2. HEIC를 읽는다(pillow-heif).
3. 회전을 바로잡고 색을 sRGB로 맞춘다.
4. 촬영일 · 기기만 내부 열에 남기고, GPS는 '있었음' 표시만 남긴다(좌표는 저장하지 않음).
5. 메타데이터를 지운 WebP 변형본을 만든다: 400 · 1080 · 2048px.
6. 흐림 미리보기(작은 placeholder)를 만든다.
7. sha256 · pHash를 계산해 중복을 찾는다.
8. (선택) 얼굴 감지로 검토 표시만 한다.

### 단계별 저장

| 단계 | 업로드 | 저장 · 서빙 |
| --- | --- | --- |
| 지금 | 브라우저 → API(`POST /files`, 크기 · 형식 검사) | 로컬 디스크 `files-data` 볼륨. 원본은 비공개, 변형본도 API가 권한을 확인하고 내보냄 |
| 운영 전환 | 브라우저 → S3 presigned POST(크기 상한을 서명에 건다) → API에 완료 알림 → 워커 | 원본은 비공개 S3, 공개 변형본은 CloudFront. 키에 해시를 넣어 영구 캐시 |

`files/storage.py`만 바꾸면 되도록 저장 위치(key) 규칙을 지금부터 같게 둔다.

### 쓰는 것

| 용도 | 고른 것 | 이유 |
| --- | --- | --- |
| 이미지 처리 | Pillow 13 + pillow-heif | 이미 Python 워커가 있다. AVIF · WebP 쓰기 지원, `exif_transpose` |
| 중복 검사 | ImageHash (pHash) | PostgreSQL `bit(64)` + `bit_count(a # b)`로 비교 |
| 큰 처리량이 필요해지면 | pyvips | 빠르고 메모리를 적게 쓴다. 지금은 필요 없음 |
| 서빙 | 미리 만든 변형본 + `<Image unoptimized>` 또는 너비 매핑 loader | Next.js 기본 이미지 최적화는 EC2 한 대의 CPU · 디스크를 같이 쓰고, v16부터 사설 IP 원본을 기본으로 막는다 |
| 나중에 크기 종류가 많아지면 | imgproxy (Docker) | 메타데이터 제거 · S3 원본 · 서명 URL 기본 제공 |
| 전후 비교 | react-compare-slider | 의존성 없음, 키보드 · 스크린리더 지원 |
| 크게 보기 | yet-another-react-lightbox | 확대 · 썸네일 · 설명 플러그인. 이음매 · 연귀 확인에 확대가 꼭 필요 |

참고:
- Next.js 쪽 sharp는 HEVC로 만든 HEIC를 못 읽는다. 변환은 Python 워커가 맡는다.
- arq는 README에 '유지보수만 하는 단계'라고 적혀 있다. 지금 규모에는 문제없지만 나중에 바꿀 수 있다는 것만 알아 둔다.

### 얼굴 · 동호수 가리기

- **MVP:**
  - 올리는 화면에 '얼굴 · 동호수 · 가족사진 없음' 확인 목록을 둔다.
  - 업체가 사진 위에 사각형을 그려 가리는 **수동 가림 도구**를 둔다. 워커는 공개 변형본에만 흐림을 적용한다.
  - 관리자가 최종 검수한다.
- **자동 감지는 나중에:** OpenCV YuNet(얼굴)이나 OCR(번호)은 '검토 필요' 표시로만 쓴다. 집 안 사진은 액자 속 얼굴을 놓치거나 잘못 잡기 쉬워서 자동으로 가리지 않는다.

## 9. 화면

**업체 · 사례 쓰기 (FFV-08)** — 한 화면에 한 묶음씩, 임시 저장

1. 기본: 제목, 공정, 지역, 평수, 공간, 끝난 달 · 기간, 비용 공개. 믿집 공사를 고르면 지역 · 평수 · 공간이 채워진다.
2. 공정 상세: 도배(벽지 · 천장 · 초배 · 끝선 · 자재), 목공(항목 추가).
3. 사진: 끌어다 놓기 → 처리 중 표시 → 사진마다 역할 · 공간 · 디테일 고르기 → 전후 짝 묶기 → 대표 고르기 → 가리기 도구.
   - 화면에 빠진 필수 컷을 체크리스트로 보여 준다(예: '도배 이음매 근접이 없어요').
4. 미리보기 → 권리 서약 → 검수 요청.

**고객 · 업체 상세 (FFW-09)**

- 사례 카드: 대표 사진, 제목, 공정, 지역 · 평수, 배지(믿집 진행 공사 / 업체 등록 사례).
- 사례 상세:
  - 대표 사진과 항목 요약(벽지 · 몰딩 규격).
  - 탭: 공간별 / 디테일 / 시공 전후(슬라이더).
  - 사진을 누르면 크게 보기와 확대.
  - 연결된 후기.

**관리자 · 사례 검수 (FAD-03 옆)**

- 대기 목록, 중복 의심 · 개인정보 표시, 게시 · 보완 요청 · 반려(사유).

## 10. 구현 순서

1. **지금 바로:** 고객이 올린 공간 사진 · 도면에도 같은 처리(회전, EXIF · GPS 제거, 변형본)를 넣는다. 지금은 원본 그대로 저장한다. 업체에게 고객 사진을 보여 주기(가견적 단계) 전에 해야 한다.
2. 사례 표 · API · 업체 쓰기 화면 · 고객 상세 화면 · 관리자 검수. 업체 등록 사례만, 배지 없이.
3. 믿집 공사 연결 · 고객 동의 · 배지(실측 · 확정 흐름이 생긴 뒤).
4. pHash 중복, 수동 가림 도구.
5. S3 · CloudFront로 이전, (선택) 자동 감지.

## 13. 정할 것

1. 외부 공사 사례를 받을지, 받으면 라벨은 '업체 등록 사례'로 할지
2. 단지명: 고객이 동의할 때만 (권장) / 기본 공개
3. 비용: 믿집 공사는 확정 금액으로 구간을 자동 계산, 외부 사례는 구간 선택 또는 비공개 (권장) / 정확한 금액 허용
4. 원본 보관: 비공개로 1년 뒤 삭제 / 영구 보관 / 처리 직후 삭제
5. 검수: 처음 3건은 사전 검수, 그 뒤는 자동 검사 통과 시 게시 + 사후 검수 / 전부 사전 검수
6. 가구 · 소품 연출 사진: 허용하되 대표 사진 외 디테일 필수 (권장) / 권장하지 않음
7. 서빙: 미리 만든 변형본 (권장) / imgproxy
8. 얼굴 자동 감지를 MVP에 넣을지
